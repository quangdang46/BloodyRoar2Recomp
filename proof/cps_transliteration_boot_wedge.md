# cps_ transliterations wedge early boot — A/B isolation proof

**Status: CONFIRMED via runtime A/B. The `cps_` bulk in `game/cps_clean.c`
(generated by `game/gen_cps_clean.py`) contains a boot-wedging bug. Named
clean ports and generated code are both healthy.**

This overturns the earlier "game is just idle / read_ram limitation" reading
(corrected in AGENTS.md). The headless instance is NOT idle — it is parked in
the documented CD deferred-coroutine / BIOS-event starvation, and the trigger
is a `cps_` transliteration, not the runtime or `read_ram`.

## Symptom (deterministic, fresh-instance repro)

Default clean dispatch, `--headless`, `Game.cue`, debug port:

- `get_registers`: frozen `ra=0xBFC05E00`, `sp=0x801FFD68`, `s0=0x00008FE0`
  (main-thread TCB — same as `proof/arcade_residual_wedge.md`), identical
  across samples and across START presses.
- `bioscall_dump`: **1,364,721 historical `B0/0x11 TestEvent`** calls —
  frozen (thread now asleep, VBlank-only wake). Matches the documented
  "DeliverEvent never reaches the flag" starvation.
- `card_mgr_trace`: 2.78M historical card-manager calls (boot probe), frozen.
- `read_ram 0x1F800000` (scratchpad `gs`/`ph`): **all zeros** — versus/title
  state never written. `gwatch` on `0x801FF000`/`0x1F800000`: zero writes.
- `clean_trace`: only 2 BIOS-called memset pieces (`0x80126178/88`,
  `ra=0xBFC06694`). `phase_profile`: 100% "other" parked loop.
- `pad_status`/`press` work (slot0 `buttons=0xFFF7`, override active) but the
  parked main thread never consumes input.

Frame counter advances (BIOS VBlank) — which is why "frames increase" was a
false health signal for many sessions.

## A/B isolation (the decisive experiment)

Two env-gated dispatch filters were added (default OFF = no behavior change):

- `PSX_NO_CLEAN=1` (`psx_game_backend.c`): skips `clean_try_dispatch` for
  EVERY guest addr → 100% generated path.
- `PSX_NO_CPS=1` + `PSX_CPS_KEEP=lo-hi[,..]` (`gen_clean_table.py` →
  `clean_table.c`): routes only `CLEAN_ENT_CPS`-flagged entries to generated;
  named clean ports (`flags&1==0`) always stay clean.

Results on identical fresh launches:

| Dispatch config | scratchpad `gs`/`ph` @0x1F800000 | verdict |
|---|---|---|
| default (named clean + all cps_) | `00 00` + zeros | **WEDGED** |
| `PSX_NO_CLEAN=1` (all generated) | `06 02` + live ptrs `0x801E40A0/10` | progressing |
| `PSX_NO_CPS=1` (named clean, cps_→gen) | **`05 00` = TITLE** | **WORKS** |
| `PSX_CPS_KEEP=0x80120000-0x80180000` | `00 00` | wedged |
| `PSX_CPS_KEEP=0x80180000-0x801C0000` | `00 00` | wedged |

**Conclusion:** `PSX_NO_CPS` reaching TITLE while default wedges proves the
bug lives in the `cps_` transliterations specifically. Named clean ports are
exonerated; generated is the healthy reference.

## Why region-bisection via `PSX_CPS_KEEP` is inconclusive

`cps_` functions chain to each other by **direct C calls** (`cps_80126188();`),
NOT through `clean_try_dispatch`. The env filter only gates the *entry*
dispatch; internal `cps_Y()` edges still execute the `cps_` body regardless of
region filtering. So "keep half the regions" still runs most `cps_` code via
internal calls — both halves wedged for that reason, not necessarily because
each half independently contains a bug. Localizing the culprit needs either:

1. A filter that also intercepts internal `cps_Y()` calls (hard — direct C
   calls, not dispatched), or
2. Tracing the wedge point: run default, find the last `cps_` entry before the
   park / the coroutine that fails to deliver its event, or
3. Commit-bisect the `gen_cps_clean.py` transform batches (sessions 12–17).

## cps_ census (for the hunt)

- 7507 `CLEAN_ENT_CPS` entries in `k_clean_dispatch` across 10×64KB regions:
  `0x80120000`–`0x8012FFFF` (1057), `0x80130000` (1787), `0x80140000` (178),
  `0x80150000` (750), `0x80160000` (276), `0x80170000` (463),
  `0x80180000` (832), `0x80190000` (1160), `0x801a0000` (972),
  `0x801b0000` (32).
- 1283 `cps_*` defs in `game/cps_clean.c`; 1052 carry `psx_check_interrupts_at`
  yield points (the IRQ-delivery mechanism — prime suspect area for a
  mistransliterated yield/resume).

## Prime suspects (transform correctness, not coverage)

The transformer (`gen_cps_clean.py`) handles: instrumentation strip,
MMIO-safe accessors, gpr[29] ownership, `lwl/lwr/swl/swr`, split-piece
fallthrough, prototypes, COP2 temps. A single mistransliterated yield,
delay-slot, unaligned access, or `cpu->pc` resume in a boot-path coroutine
starves the DeliverEvent → TestEvent park. The bug is a *correctness* defect
in generated output, orthogonal to the readability/coverage work — coverage
was proven (0 dispatch misses) but correctness was only ever verified by
"frames advance," which a wedge satisfies.
